# level0 · 测出你的噪声地板

> 对应 `AI系统工程师-学习路线.md` 的 **阶段 0**。
> 这个目录和你的项目没有任何关系，是全新的、从零开始的东西。

**目标**：在改进任何东西之前，先测出"什么都不改"时分数会晃多少。这个晃动幅度就是你的**噪声地板**。

---

## 一、准备 API key

去 https://platform.deepseek.com/api_keys 注册 → 建一个 key → 充几块钱。

**key 放哪儿？脚本按这个顺序找**，找到一个就用：

| 顺序 | 方式 | 怎么做 |
|---|---|---|
| 1 | 环境变量 | `$env:DEEPSEEK_API_KEY="sk-你的key"`（PowerShell，每次新窗口都要设） |
| 2 | 本地文件 | 在本目录放 `myKey.txt`，**文件内容就是 key 本身**，不要有引号、空格、换行以外的任何东西 |

你这个目录下已经有一个 `myKey.txt` 了，脚本会尝试读它。

> ⚠️ **两件事**
> 1. 这个文件**绝对不能提交到 git**。同目录已经放了 `.gitignore` 帮你挡住。
> 2. 如果你那个文件里不是 DeepSeek 的 key，脚本会报认证错误——那就改用环境变量。

## 三、两个脚本各干什么

### `stage0_a_temperature.py` —— 先看清"随机"本身

同一句话，用 `temperature=1` 和 `temperature=0` **各问 20 次**，数一数出现了几种不同回答。

| 你会看到 | 说明 |
|---|---|
| `temperature=1` → 好几种不同回答 | 模型每次在随机挑词 |
| `temperature=0` → 几乎全都一样 | 固定住随机性，输出就稳定了 |

如果 `temperature=0` 也出现好几种回答，**别当成 bug，这是个重要发现**：说明"同一个请求问两次"本身就不完全可靠。这件事后面做 eval 时必须知道。

顺手还会给你延迟的 P50 / P95 和 token 用量。单价去 https://api-docs.deepseek.com/zh-cn/quick_start/pricing 查，乘一下就是钱。

### `stage0_b_noise_floor.py` —— 把两个抖动都测出来 ★ 核心

用一套有确定答案的小题（乘法），**整套连跑 5 遍**，一次算出两个独立的抖动来源：

| 抖动 | 怎么来的 | 意味着什么 |
|---|---|---|
| **采样抖动** | 同一套题、同一份代码，连跑 5 遍得到 5 个分数 | 因为 `temperature>0`，每次答得不一样 |
| **数据集抖动** | 从这套题里随机抽一部分算分，重复很多次 | 因为题太少，抽到哪些题会影响分数 |

**这就是 level0 的全部意义**：你什么都没改，分数却在晃。

> 如果模型全对（或全错），脚本会自己提醒你——**一个所有人都考 100 分的测试是没有区分度的**。按提示把 `DIGITS` 改大或改小再跑。
>
> `DIGITS` 默认已改成 **4**。原因：实测 deepseek-flash 在 3 位数乘法上 5 遍全对，测不出任何抖动。

### `stage0_c_temperature_effect.py` —— 回答"为什么 T=0 也不确定"

**这是跑完 `stage0_a` 之后必然会冒出来的问题。** 实测中 `temperature=0` 的 20 次给出了 20 种不同回答，两种可能：

| 可能 | 含义 |
|---|---|
| 甲 | temperature 生效了，但**服务端本身有非确定性**（MoE 路由 / 批处理 / GPU 浮点归约顺序），而且会随生成长度放大 |
| 乙 | `temperature=0` 被服务端当成"没传"，实际按默认值 1 在跑 |

脚本用两个任务把它们区分开：

- **任务 1（短，1 个 token）**：从三个词里选一个
  T=0 收敛到某一个词 + T=2 摊开 ⇒ 排除乙，temperature 确实生效
- **任务 2（长，几十个 token）**：解释一句话
  T=0 下仍然各不相同 ⇒ **噪声在生成过程中被累积放大了**

如果两个都成立，你会得到 level0 最重要的一条结论：

> **T=0 提高可复现性，但不保证可复现。**
> 所以「噪声地板」这件事，绕不过去 —— 即使你把 temperature 设成 0。

## 四、跑完要交的东西

脚本会自动生成 `level0/notes/00-noise-floor.md`，里面长这样：

```
我的采样抖动      是 ±___%
我的数据集抖动    是 ±___%
跑一次 eval 要     ___ 分钟 / ___ 元
结论：小于 ___% 的改进，用我现在的 eval 是测不出来的
```

数字脚本会帮你填，但**其中两行要你自己想清楚**：

- **成本那一行**：脚本告诉你用了多少 token，单价你自己去定价页查了乘
- **最后那行结论**：这是整条路线的起点。它决定了你后面能相信多大的改进

## 五、卡住了怎么办

| 症状 | 原因 |
|---|---|
| `没找到 API key` | 环境变量没设，且本目录没有 `myKey.txt` |
| `AuthenticationError` | key 错了 / 没充值 / `myKey.txt` 里不是 key（可能混进了引号或说明文字） |
| `ModuleNotFoundError: openai` | `pip install openai` |
| 报错提到 `model` | 模型名可能变了，去 https://api-docs.deepseek.com/zh-cn/ 查，改脚本顶部 `MODEL` |
| 脚本说"题太简单/太难" | 改脚本顶部 `DIGITS`，然后重跑 |

**两个脚本顶部都有「配置区」，只有那几行需要改，其他都不用动。**

### ⚠️ 关于 `00-noise-floor.md` 的当前状态

里面那份数据（±0.0%）是**无效的**——模型在 3 位数乘法上 5 遍全对，
题目没有区分度。文件开头已经加了警告。**用重写后的脚本 B 重跑会覆盖它。**

### ⚠️ 关于 `stage0_c` 的已知局限

脚本 C 的**任务 1 是个失败的控制组**：prompt 里写了"随机选一个"，
等于命令模型把概率压平，导致 T=0 没有第一名可收敛、T=2 没有空间可摊开，
上下都没有区分度，**区分不出"temperature 生效"和"被忽略"**。

脚本里保留了它，就是为了让你看到"没有区分度的实验"长什么样。
下次设计对照组的正确做法见 `00-level0-总结.md` 第三节。
