# 概念笔记 · temperature

> level0 配套笔记。看完这个你应该能回答：temperature 是什么、为什么需要它、什么时候该调它。

## 一句话

**temperature 是"从模型给出的候选里抽签的随机程度"。**
0 = 每次拿第一名；1 = 按原概率抽签；越大越乱。

---

## 二、模型不输出文字，它输出一张候选表

每次调用，模型内部算的不是"一句话"，而是：

> 给定我看到的所有内容，**下一个词**是每个可能词的概率各是多少？

比如输入 `今天天气真`，它算出来的原始分数（叫 **logits**）是：

| 候选词 | 原始分数 |
|---|---|
| 好 | 4.0 |
| 不错 | 3.0 |
| 糟 | 1.0 |
| 蓝色 | -2.0 |

**它一次只决定一个词。** 选完"好"，就把"好"接到输入后面，再跑一遍，决定下一个词。
所以一句话 50 个词 = 模型跑了 50 次。

---

## 三、temperature 插在哪

模型算完分数表之后，要把它变成概率然后抽签。temperature 在"变概率"之前把分数统统除以 T：

```
概率 = exp(分数 / T) ÷ 所有候选的 exp(分数 / T) 之和
```

**同一张分数表（模型完全没变），只改 T：**

| 候选词 | T = 0.5 | T = 1（原样） | T = 2 |
|---|---|---|---|
| 好 | **87.9%** | **70.4%** | **53.2%** |
| 不错 | 11.9% | 25.9% | 32.3% |
| 糟 | 0.22% | 3.5% | 11.9% |
| 蓝色 | 0.0005% | 0.17% | **2.6%** |

- **T 调小** → 概率被拉得更悬殊 → "好"几乎垄断 → 输出**稳定**
- **T 调大** → 概率被抹平 → "蓝色"这种原本几乎不可能的选项，居然有 **1/38** 的概率被选中 → 输出**发散、甚至胡说**
- **T = 0** 是极端情况：不抽签了，直接取分数第一名（叫**贪心解码**）。所以 `temperature=0` 不是"除以 0"，API 内部实现成"直接选第一名"

---

## 四、三个必须记住的结论

**1. temperature 不改变模型"知道"什么，只改变"怎么挑"。**
上表三列里，模型算出的分数**一模一样**。它没变笨也没变聪明。
**模型负责出分数，temperature 负责决定你信不信这个分数。**

**2. 为什么 T=1 时输出差异大得离谱？**
因为它是几十次连续抽签。第一个词如果抽到了 25.9% 的"不错"而不是 70.4% 的"好"，**后面整句走向就全变了**——新输入不一样了，下一轮的概率表也不一样。小分叉被层层放大。
这就是 `stage0_a` 里"20 次出现十几种回答"的原因。

**3. 它是推理时的参数，不是模型的一部分。**
没有训练、没有权重被改动。你在请求里传一个数，服务商在**模型算完之后**用它决定怎么抽。

---

## 五、为什么不能干脆把 T 设到最小？★

这是最容易想错的地方。**T=0 不是"更好"，它只是"另一种行为"。**

### 1. T=0 把不确定性**藏起来**，而不是消除它

模型内部那张概率表还是"好 70% / 不错 26%"——它照样不确定。
argmax 只是**强行挑了第一名**，然后表现得很自信。

> **你要治理不确定性，就必须能看见它。而 T=0 正好把它蒙上。**

### 2. 稳定 ≠ 正确

T=0 给你的是"每次都一样"，**不是"每次都对"**。
如果模型错了，它会**稳定地错**。一个稳定犯 30% 错的系统，还是 30% 错。

很多人把"确定性"当成"可靠"，这是个危险的混淆。你要的是
**"准确率高，而且我知道它什么时候不准"**，不是"每次都一样"。

### 3. 贪心解码有已知的退化问题

每次只挑当前最优的 token，**不等于整句最优**。局部最优会累积成
死循环、重复、内容空洞。这个现象有篇很出名的论文专门讲：
*The Curious Case of Neural Text Degeneration*（Holtzman et al., 2019）——
它也是 `top_p` 这个参数的出处。

### 4. 有些任务要的就是多样性

起 10 个标题、生成 5 套方案、合成训练数据——
T=0 时你跑 10 次拿到 10 个**一模一样**的，等于只拿了 1 个。

### 5. 后面阶段 4 的自一致性，必须有 T > 0

我们要测"模型对这题到底有没有把握"，方法是同一题采样 5 次看散不散。
**T=0 时 5 次完全一样，你永远测不出不确定性。**

### 6. 反直觉的一点：T>0 反而可能更准

**自一致性（self-consistency）**：同一道推理题，在 T>0 下采样 5 次，
取多数答案——在多步推理任务上，**这个结果的准确率常常高于 T=0 单跑一次**。

所以"T 小 = 准"是错的。T 小只是"稳定"。

### 核心那句话

> **T=0 是把模型当成一个函数 `y = f(x)`。**
> **T>0 是把模型当成一个分布 `P(y|x)`。**
>
> 你要"治理不确定性"，就必须看见那个分布。
> 把 T 设成 0，等于把分布上的一个点当成全部真相。

## 六、什么时候用哪个

| 场景 | 建议 T | 为什么 |
|---|---|---|
| 跑 eval、回归测试 | **0** | 要可复现，不然分数自己在晃 |
| 事实问答、结构化抽取 | 0 ~ 0.3 | 要稳定、要格式一致 |
| 代码生成 | 0 ~ 0.3 | 要能跑、可复现 |
| 对话、写作 | 0.7 ~ 1.0 | 太死板会显得僵硬 |
| 头脑风暴、合成数据 | 1.0 ~ 1.5 | 要的就是多样性 |
| **测不确定性（阶段 4）** | **> 0** | 不加随机性就没有信号可测 |

**不要同时调 temperature 和 top_p。** 日常只调一个。

---

## 七、两个常见参数

| 参数 | 做什么 | 一句话 |
|---|---|---|
| `temperature` | 把所有概率**重新缩放**（变形） | 拉平或拉开 |
| `top_p` | 先砍掉尾巴，只留累积概率达 p 的候选，再重新分配（**截断**） | 扔掉长尾 |

**默认值**：多数 API 不传 temperature 时默认是 **1**。
所以"我什么都没设，为什么每次结果不一样"——答案就在这。

**T=0 也不保证 100% 逐字相同。** 服务端批处理、MoE 路由、GPU 浮点误差
都可能带来微小差异。这件事 `stage0_a` 会帮你亲眼验证。

---

## 八、常见误解

| 误解 | 实际 |
|---|---|
| T 越大模型越聪明 | T 只改抽签方式，不改模型能力 |
| T=0 就一定会更准 | T=0 只是更**稳定**；稳定地错也是错 |
| T 是最优解，越低越好 | 不同任务不同，测不确定性时 T=0 直接失效 |
| T=0 就是完全确定 | 服务端仍有非确定性，要实测 |
| T 和 top_p 一起调效果更好 | 两个都会改分布，一起调会互相打架 |
