# level1 · 最小 LLM 程序

> 对应学习路线的 **阶段 1**。
> **产出物**：一个可观测、可容错、**内网就能开发和验收**的模型调用封装。

---

## 一、约束 → 设计

你的约束是：**公司内网，调不了外部模型。**

所以这里做了一个关键的设计决策：

> ### 不 mock「函数」，mock「服务端」

在你自己机器上跑一个**假的 API 服务器**。你的代码照样**真的发 HTTP 请求**、真的收状态码、真的解析 JSON——只不过目标是 `127.0.0.1`，不走外网。

```
  你的 llm.py  ──HTTP──▶  mock_server.py（本地，假模型）
                          │
                          └─ 可以模拟：慢响应 / 429 / 500 / 401 /
                                      坏 JSON / 空回答 / 前两次失败
```

**回家只需要改一行：**

```python
BASE_URL = "http://127.0.0.1:8000"       # 内网：假服务器
BASE_URL = "https://api.deepseek.com"    # 回家：真模型
```

代码一行都不用动。**内网能完成 level1 的 95%**，而且覆盖的是真实的 HTTP 路径——超时、状态码、重试、解析，全都是真的在跑。

### 而且这个设计本身就是必修课

不是因为公司有限制才这么做，是真实工程需要：

- 你以后要在多个模型之间切换（比价、降级、灰度）
- CI 里不可能调外部 API，**必须有假的**
- 线上出问题时，要能录下真实样本重放

说到底就是你后端的老本行——**mock 外部依赖**。只不过这次 mock 的对象是模型，而且这次是在 **HTTP 层** 而不是函数层 mock。

## 二、谁写什么

| 文件 | 谁写 | 说明 |
|---|---|---|
| `mock_server.py` | **我写好了** | 脚手架。本地假模型服务器，只用标准库，不用 pip |
| `check.py` | **我写好了** | 脚手架。9 组验收测试 |
| `llm.py` | **你写** | ★ 学习对象。里面有 5 个 TODO |
| `calls.jsonl` | 自动生成 | 每次调用的记录 |
| `notes/01-llm-封装.md` | **你写** | 结论笔记 |

**两个脚手架文件不用看懂每一行。** `llm.py` 要你自己写——那 5 个 TODO 就是 level1 的全部内容。

**不需要 pip install 任何东西。** 两个脚手架只用标准库（`http.server` + `urllib`），内网环境也能跑。

## 三、步骤

### Step 0 · 把假服务器跑起来（离线，20 分钟）

```powershell
# 先 cd 到本目录（家里：D:\mywork\sandbox\level1；公司：克隆下来的 AI_STUDY\level1）
python mock_server.py
```

看到 `假模型服务器已启动` 就成了。**让它一直开着**，另开一个窗口做后面的步骤。

想确认它工作，可以在第三个窗口试一下：

```powershell
curl.exe -X POST http://127.0.0.1:8000/chat/completions -H "Content-Type: application/json" -d '{\"model\":\"mock-normal\",\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}]}'
```

### Step 1 · 写 `llm.py`（离线，约 2～3 小时）

打开 `llm.py`，把 5 个 TODO 补完。每个 TODO 都有详细的提示，包括：

- **TODO 1** 发一次 HTTP 请求（`urllib.request`）
- **TODO 2** 区分成功和失败，把错误分类（超时 / 认证 / 限流 / 服务端 / 网络 / 解析）
- **TODO 3** 决定重试还是放弃（**认证失败不重试，限流和服务端错误要重试**）
- **TODO 4** 写日志到 `calls.jsonl`
- **TODO 5** 返回结果字典

写一个 TODO 想马上看效果，就跑：

```powershell
python llm.py
```

### Step 2 · 跑 `check.py`，跑到全绿（离线，约 30 分钟）★ 验收点

```powershell
python check.py
```

9 组测试，覆盖：

| # | 测什么 | 关键点 |
|---|---|---|
| 1 | 正常路径 | 字段齐全、attempts == 1 |
| 2 | 超时 | `timeout=1` 对 `mock-slow`（睡 3 秒） |
| 3 | **认证失败不该重试** | `max_retries=3`，但 attempts 必须 == 1 |
| 4 | 服务端 500 应该重试 | `max_retries=2` → attempts == 3 |
| 5 | 限流 429 应该重试 | 且要认 `Retry-After` 头 |
| 6 | 坏 JSON | 要被抓成 `parse`，不能崩 |
| 7 | 空回答 | HTTP 200 也不算成功 |
| 8 | **重试真的能救回来** | 前 2 次 500，第 3 次成功 |
| 9 | 日志 | 字段齐全，且失败的调用也记了 |

**全部通过 = level1 的工程部分过关。而且全程不需要联网。**

> 第 3 条和第 4 条是这道题的核心：
> **同样是失败，为什么 401 不重试、500 要重试？**
> 想清楚这个，你就懂了"重试"到底在解决什么问题。

### Step 3 · 接真模型（联网，约 30 分钟，回家做）

改 `llm.py` 顶部三行：

```python
BASE_URL = "https://api.deepseek.com"
MODEL = "deepseek-flash"
API_KEY = "<你的真 key>"
```

**然后先跑 `python llm.py` 确认能通**，再跑 20 次同一个问题，记录：

- 真实失败率是多少？（可能不是 0）
- 延迟 P50 / P95 各多少？和 level0 测的对得上吗？
- 我的重试逻辑在真实环境下触发过吗？

### Step 4 · 结构化输出（离线 1.5 小时 + 联网 0.5 小时）

让模型返回 JSON。

**离线**：新增一个 `mock-badjson2` 模式（或自己造），把解析器的失败情况测全：
缺字段、多字段、类型不对、被 markdown 代码块 ```json 包住、前面有多余解释文字。

**联网**：真模型跑 30 次，数**几次解析失败**。

> 这个"解析失败率"是真实的工程数字。
> 很多线上事故就是"模型 99% 返回合法 JSON"——那 1% 你没处理。

### Step 5 · 采集真实数字（联网，约 40 分钟）

跑一批长度不同的请求，从 `calls.jsonl` 里统计（不是靠感觉）：

- 输入 1000 字 / 4000 字 / 10000 字的延迟和成本各差多少
- 输出 50 字 / 500 字的延迟差多少
- **跑一次 50 题的 eval 要多少钱、多少时间**

这个数字决定你 level3 能做多少次实验。

### Step 6 · 写笔记（约 40 分钟）

`notes/01-llm-封装.md`，回答：

- 我的封装在哪些情况下会失败？
- 真实模型的失败率、延迟分布、解析失败率各是多少？
- 如果放到生产，我最不放心的是什么？

## 六、不要做的事

| 不要 | 为什么 |
|---|---|
| 用 LangChain / LlamaIndex | 会把机制藏起来。level1 的全部意义就是把机制暴露出来 |
| `pip install openai` 然后照抄示例 | 内网可能装不了，而且 SDK 帮你藏掉了 HTTP 细节——那些细节正是你要学的 |
| 一上来设计"通用多模型适配层" | 过早抽象。先把一个模型调通 |
| 追求"完美错误处理" | 先覆盖 check.py 那 9 组，其他等真的遇到再加 |
| 把 `calls.jsonl` 提交进 git | 里面有你的 prompt 内容，可能含敏感信息 |

## 七、自检问题

答不上来就说明还没做完：

1. 我的 `call_model` 遇到限流会怎么做？遇到认证失败呢？**为什么两者不一样？**
2. 我怎么知道今天成本涨了 30%？——**靠哪个文件、哪个字段？**
3. 如果明天要换成另一个模型，我需要改几行代码？
4. **重试会不会把一次失败变成三次计费？** 我该怎么测这件事？
5. `calls.jsonl` 为什么会越写越大？生产环境该怎么处理？
6. 假服务器能模拟"HTTP 200 但内容是空的"，真模型会这样吗？我凭什么知道？

> 第 4 题是个真实的坑：**重试会重复计费**。
> 很多时候失败的那次请求服务端也算了钱。Step 5 统计成本时要留意。
>
> 第 6 题是 level1 最重要的反思：
> **假服务器只能模拟你想到的情况。** 真实模型会给你没想到的。
> 所以 Step 3 之后，要拿真实数据回头补假服务器的模式。
